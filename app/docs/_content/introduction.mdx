## What AXe does

AXe is one binary you install with Homebrew. Every command names its target with `--udid`, and the same commands work on a simulator, an iPhone Duo simulator and a paired iPhone or iPad. Use it from a terminal, a shell script, a CI job or an AI agent.

## A first session

```shell
axe list-simulators                       # find a booted simulator's UDID
export UDID=<UDID>
axe describe-ui --udid "$UDID"            # accessibility tree as JSON
axe tap --label "Continue" --udid "$UDID"
axe type 'Hello world' --udid "$UDID"
axe screenshot --udid "$UDID" --output screen.png
```

For a physical device, use `axe list-devices` and `axe doctor` instead of `list-simulators`; the rest is the same. See [Physical iPhone & iPad](/docs/physical-devices).

<Callout variant="info" title="Coordinates are points, not pixels">
Coordinates are logical points in the current orientation, the units `axe displays` reports. A screenshot contains pixels. AXe handles rotation and letterboxing for you.
</Callout>

## Two ways to drive the UI

| Route | Use it for | How it works |
|-------|-----------|--------------|
| Plain commands | Scripts, CI and known flows | Send input by point or selector. Fast and simple; you check the result with a separate read. |
| Agent mode (`--agent`) | AI agents and flows that must not hit the wrong control | Capture the screen as rows with refs, act on a ref, and get the settled screen back. AXe refuses input if the control changed. |

Read [Agent Mode](/docs/agent-mode) before connecting an AI agent to AXe, and install the [AI skill](/docs/agent-skills) so the agent knows the workflow.
